## Approach

* **Hub.** `CertifiedTorusAt c ω* K∞ s∞` is the body of `CertifiedTorus` with the witnesses named
  (`certifiedTorus_iff` is `Iff.rfl`); every adapter is a lemma on it, so graph, transport and
  observables attach to the same exact torus (LG00's `lg00TorusWith` is its `n = 2` case).
* **Real model torus.** For an exact torus of a Hamiltonian `h` holomorphic and real on an open `D`
  (`IsRealHolo`), `k = Re K∞ ∘ ι` is analytic, `k(θ + m) = k θ + (m, 0)`, its lines solve
  Hamilton's equations of `realHam h = Re h ∘ ι` (frozen orientation), and `realHam h ∘ k = E₀`
  (`KAM.real_restriction`, `KAM.hamiltonianVectorField_eq_of_real`).
* **Graph (item 1).** Pure lemma: `‖DA - 1‖ ≤ L < 1` on `ℝⁿ` ⇒ `A` bi-Lipschitz, bijective
  (fixed point of the contraction `x ↦ x + (y - A x)`), a homeomorphism with analytic inverse
  (`Homeomorph.contDiff_symm` at order `ω`). For the certified torus: Cauchy on polydiscs of radius
  `< ρ∞` around real points gives `‖DK∞ - DK‖ ≤ disp/ρ∞` at real points, so
  `‖DA - 1‖ ≤ δ + disp/ρ∞` from the candidate's angle-block bound `δ`. **Checkable condition:**
  `AngleNearId c δ` (`Σ_j |∂_j U_i| ≤ δ` on the real torus, every row) and `δ + disp/ρ∞ < 1`;
  `checkAngleGraph c δ` checks both with the `compDerivModel` sup bounds `checkEmbedding` already
  uses (no new numerical claim type).
* **Transport (item 2).** The transport identity `DΨ X_{Hc} = κ F ∘ Ψ` on `O`
  (`IsFieldTransport`, physical space any real normed space, any variable order) carries orbits
  (`τ ↦ Ψ(y(τ/κ))`), tori (`IsPhysicalFlowTorus F (κ⁻¹ ω) (Ψ ∘ k)`), energy levels
  (`Hc = a · H_phys ∘ Ψ` ⇒ level `E₀/a`), lattice laws, injectivity mod `ℤⁿ`, immersion and
  analyticity. It generalizes `lg00_transport` and SO-3's `lock_conjugacy` (both are instances,
  see the design note), and follows from the core's `IsChart` (`isFieldTransport_of_isChart`).
* **Observables (item 3).** Enclosures of the certificate's own real torus transfer by the mean
  value inequality on a convex set (`Λ disp`), coordinates by `disp`, derivatives by `disp/ρ∞`,
  the physical frequency by `disp/|κ|`; `checkActionRange` checks an action interval from the strip
  model used by `checkEmbedding`. Orbits on the torus stay on it (`forall_orbit`).
* **Contract (item 4).** `APPLICATION-CONTRACT.md`: the improvements-doc §7 table with the Lean
  carrier of each row, the module map, exact statements, and the SO-2, SO-3 and LG00 instances
  (recipes with exact Lean names).

## Owner questions

1. **Weaker graph criterion.** `AngleNearId` asks `‖DU‖ < 1`. SO-2/SO-3 use a clock-triangular
   criterion (only `∂_{θ₀} Q ≥ m > 0`). Should the core adapter also provide that (or the general
   one: `DA` invertible everywhere, via Hadamard's global inverse theorem, not in Mathlib)?
2. **Test in the default build.** `KAM.Application.Tests.Toy2` is cheap (≈ 6 s) but reaches
   3.0–3.8 GB because of the Mathlib import of the chart layer. Keep it in the core build, or make
   the chart part opt-in?
3. **`lg00TorusWith`.** It is `CertifiedTorusAt` at `n = 2` verbatim; the LG00 package could use
   the core definition (one less copy). Owner/certside decision.
4. **Names.** `CertifiedTorus.exists_realGraph(_of_checks)` live in `KAM.Application.CertifiedTorus`
   (not reachable by dot notation from `KAM.Certificate.CertifiedTorus`); keep them there, or move
   them into the `KAM.Certificate.CertifiedTorus` namespace for `hT.exists_realGraph`?

  is stated, as in the frozen planetary predicates, as a homeomorphism of `ℝⁿ` commuting with `ℤⁿ`
  plus injectivity modulo `ℤⁿ`, not with a quotient type.
